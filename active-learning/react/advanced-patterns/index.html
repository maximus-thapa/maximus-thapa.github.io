    🧩 Advanced React Component Patterns

    In this guide, we'll explore powerful component patterns that promote reusability, flexibility, and clean separation of concerns in React.

    📌 What You'll Learn

    • Compound components
    • Higher-Order Components (HOCs)
    • Render props
    • Controlled vs uncontrolled components
    • Custom hook pattern (overview)

    🧱 1. Compound Components

    ✅ Concept:

    A group of components that work together and share state via context.

    Example: <Tabs> and <TabPanel> that coordinate internally.

    function Tabs({ children }) {
  const [activeIndex, setActiveIndex] = useState(0);
  return (
    <TabContext.Provider value={{ activeIndex, setActiveIndex }}>
      {children}
    </TabContext.Provider>
  );
}

function Tab({ index, children }) {
  const { activeIndex, setActiveIndex } = useContext(TabContext);
  return (
    <button
      onClick={() => setActiveIndex(index)}
      style={{ fontWeight: index === activeIndex ? "bold" : "normal" }}
    >
      {children}
    </button>
  );
}

function TabPanel({ index, children }) {
  const { activeIndex } = useContext(TabContext);
  return index === activeIndex ? <div>{children}</div> : null;
}

    🧠 Feynman Check

    "Compound components let children communicate implicitly through shared context."

    🌀 2. Higher-Order Components (HOC)

    ✅ Concept:

    A function that takes a component and returns a new one with added props/behavior.

    function withLogger(WrappedComponent) {
  return function EnhancedComponent(props) {
    useEffect(() => {
      console.log("Mounted:", WrappedComponent.name);
    }, []);
    return <WrappedComponent {...props} />;
  };
}

const LoggedButton = withLogger(Button);

    🧠 Why use HOCs?

    • Reuse logic across many components
    • Keep component tree clean

    ⚠️ Gotchas:

    • Harder to debug
    • Prop collision
    • Not as popular now (custom hooks preferred)

    🔄 3. Render Props

    ✅ Concept:

    Instead of JSX children, you pass a function as a child to a component.

    function MouseTracker({ children }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  useEffect(() => {
    function handleMove(e) {
      setPos({ x: e.clientX, y: e.clientY });
    }
    window.addEventListener("mousemove", handleMove);
    return () => window.removeEventListener("mousemove", handleMove);
  }, []);
  return children(pos);
}

<MouseTracker>
  {({ x, y }) => (
    <p>
      Mouse at {x}, {y}
    </p>
  )}
</MouseTracker>;

    🧠 Great for:

    • Reusing logic across UI (before hooks existed)
    • Encapsulating behavior while keeping rendering flexible

    🧭 4. Controlled vs Uncontrolled Components

    🔹 Controlled

    State is managed by React (via props/state)

    <input value={value} onChange={(e) => setValue(e.target.value)} />

    🔸 Uncontrolled

    State is inside the DOM, accessed via ref

    <input ref={inputRef} />
    • ✅ Controlled = better for validation, state sync
    • ✅ Uncontrolled = better for performance, third-party libraries

    🧩 5. Custom Hook Pattern (Preview)

    Instead of HOCs or render props, we often now write custom hooks to reuse logic.

    function useHover() {
  const [hovered, setHovered] = useState(false);
  const ref = useRef(null);

  useEffect(() => {
    const node = ref.current;
    node?.addEventListener("mouseenter", () => setHovered(true));
    node?.addEventListener("mouseleave", () => setHovered(false));
    return () => {
      node?.removeEventListener("mouseenter", () => setHovered(true));
      node?.removeEventListener("mouseleave", () => setHovered(false));
    };
  }, []);

  return [ref, hovered];
}

    Use it like:

    const [ref, isHovered] = useHover();
return <div ref={ref}>{isHovered ? "Hovering!" : "Hover me"}</div>;
